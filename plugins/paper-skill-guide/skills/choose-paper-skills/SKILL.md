# 论文技能推荐

## 确定本轮的任务

先看用户要求、前面的选择和已提供的材料。判断当前阶段、可用证据、交付格式、必须满足的规则和时间。题目尚未确定、已有若干论文待整合、投稿后需要答复审稿人，这三种情形需要的工作不同。

- 用户首次提出写作任务时，默认先让用户选择技能。信息足够，这条回复就给出有编号的技能比较、推荐的单项或组合，以及选择方式。现有材料不足以起草全文，也可能足以比较方案。
- 只有某个未知条件会改变推荐顺序，才问一个最有区分度的问题。已在消息、附件或课程要求里说明的条件直接采用。
- 当用户点名执行技能、回复了上轮选项，或者说“你来选”“按推荐做”时，直接执行。用户说“先比较，等我选”时，在比较后等答复。
- 单纯询问某篇论文的方法、术语或结果时，直接解决阅读问题。

## 找到真实可用的候选

使用当前工作目录的 Codex 技能清单，纳入已启用的项目技能、个人技能和插件技能。保留宿主提供的完整调用名，包括命名空间。多个技能显示名称相近时，根据完整调用名、来源和入口文件区分。排除本推荐入口自身。

清单不完整、安装状态刚变更，或无法分辨同名条目时，从用户的工作目录用 Python 3 执行本入口旁的 `scripts/list_enabled_skills.py`。用脚本的绝对路径启动，以保留用户当前的工作目录；也可用 `--cwd` 指定项目。脚本从本机 Codex CLI 获取已启用项，每行 JSON 给出名称、描述和入口路径。如果查询不可用，在对话中已能核实的清单范围内继续。

根据描述选出可能有关的技能，再读候选的实际入口，核对所需输入、步骤、可交付物、适用条件和关键依赖。先把这些信息用于比较，选定后再启动对应流程。遇到外部工具或数据库要求，区分技能中写明的能力与该环境已验证可用的能力。

## 推荐与交接

优先满足课程、期刊或其他明确要求，再比较用户已有材料、时间成本及交付质量。通常给出三个左右有实质差异的选项；选题任务也可以有多种方法。有一个合适就推荐一个，一个也没有就指出具体缺口，并给出凭现有材料可以完成的步骤。

每个编号写明完整的 `$技能标识`，结合本次任务说明四点：从哪些材料入手、会做什么、用户会得到什么、什么情况下选它更合适。用一个具体取舍说明排序，例如整理已有笔记可以直接支持短篇课程综述，而需要保留检索式和筛选记录的系统综述会增加前期工作。

技能互补时，推荐可以整组选择的执行顺序，说明一项的产物怎样成为下一项的输入。例如把入选文献和筛选理由交给写作技能，再把综述结论和关键图表交给汇报技能。选项编号应保持清楚，让用户能回复单项、几个编号或整个组合。

## 执行选定方案

接到选择后，加载选定技能的完整说明，利用已有输入立即开始可执行的工作。用户委托代选时简述理由，在同一轮交付实际结果；缺少下一步必需的材料才向用户索取。初次推荐尚待选择时，先交付比较。

在同一对话中沿用确认过的方案。常规的阶段切换直接继续，目标或硬性要求发生变化时才重新比较受影响的部分。以实际产物、处理结果和剩余输入交接。
